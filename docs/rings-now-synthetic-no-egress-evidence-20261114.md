# Rings Now：合成FIT動的観測・外部送信／永続保存の検証（2026-11-14）

## 目的と結論の限界
PR #122の「方式A（公開HTTPS＋iPhone端末内解析）は暫定第一候補、14条件の証跡が必要」を受け、**合成FITだけ**で既存の端末内解析コードの動的実行を観測する追加証拠を収集する。

このPRはテスト・文書・専用CIの**新規3ファイルのみ**で、公開画面、JavaScript本体、FIT解析エンジン、SW、DB、カレンダー、feature flagは変更しない。**実FITを使わず、試験用画面を公開しない。**

## 観測の範囲
- 既存の監査済み公開合成5km FIT（294バイト）を、既存のSHA検証 → FIT入力ゲート → ローカル解析へ流し、5区間の未認証参考結果だけを取得する。
- Nodeのglobalにfetch/XHR/WebSocket/EventSource/Worker/Storage等の**利用検知用トラップ**を置き、指定した合成1ケースにおいて呼び出しを観測しないことを確認する。トラップはfinallyで復帰する。これは**実行したコード経路の限定的証拠**であり、iPhone Safariの実通信、window/document/navigation、全副経路を観測したわけではない。
- ハッシュの異なる同名同サイズのFITをパーサーが読まないこと、非同期読み取り中の失効で解析しないこと、パーサーが余分に返した個人識別子・GPS・心拍が結果から出ないことを検証する（個人データはダミー文字列）。
- PR #121の静的import依存スキャナーを合成専用ページに実行し、検査結果を **requires_manual_review** に固定する。本番入口のOFF・開始時刻nullも検査。

## 何が未検証か
**zeroRealFitUploadPath / noBinaryOrMetadataEgress / noPersistentFitStorage は、このテストがPASSしても方式Aの14条件として「証拠完備」にしない。** なぜなら実機SafariやHTTPキャッシュ、DOMの外部送出、全依存分岐、古いタブ、ブラウザ拡張、環境の実行時挙動などが未検証だから。トラップに引っかからなかったことを「外部送信が絶対に起きない証明」と言い換えない。ブラウザのファイル選択時に選んだバイトのメモリ実消去も保証しない。

## 次の具体的な検証
1. 方式Aの候補コードと全依存を監査して、通常ナビゲーション・画像URL・フォーム・通信・保存・外部読み込みなど副経路を列挙し、脆弱性のあるものは遮断する。
2. 公開合成ページを使った**iPhone Safari実機**で、操作前後のネットワーク経路を監査できる方法を別途決める。iPhone/追加費用0円で可能な範囲と限界を明示。
3. 古いHTMLタブ・CDN/HTTPキャッシュ・SWを含めた配信撤去手順を確認。
4. 上記が完了して初めて、実FIT用ページ公開／本人端末での実FIT使用／本番ONの**それぞれ**について独立監査と本人の明示承認を取る。
5. 同一ランの推測紐付けをしない、本人が選ぶガチランと8日＝691200秒（提供開始時刻nullはOFF）、品質欠損時の注意書きは維持。

注意書き：**信号待ちやトイレ休憩、自動ポーズなどの影響により、正しく分析できない場合があります。**

## むせ独立監査
- 新規3ファイルのみか。既存公開ページ／入口／SW／DB／解析エンジンが不変か。
- 合成FITと既存SHAゲート・入力ゲート・解析を通すテストで、トラップの対象と解除、合成5区間、未認証フラグ、ダミー個人情報の除外が妥当か。
- テスト未実施の副経路とSafari実機を「送信ゼロ証明」と誇張していないか。
- 本番OFF・実FIT不使用・方式A未承認を守っているか。
- 最新CIと既存合成FIT回帰に失敗がないか。
- **監査のみ。本人の別途承認前にマージ禁止。**
