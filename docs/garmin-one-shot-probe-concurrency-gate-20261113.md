# Garmin 一度だけの形状検査：競合・失効・受信非干渉ゲート（2026-11-13）

**状態：監査用設計／本番未実装・未承認**。PR #67 Draft、#68 HOLD。既存の年輪、Push endpoint、Secret、DBを変更しない。

## 重要な発見：形状集計器は「一度だけ」を保証しない
`src/garmin-sample-shape-probe.mjs` の `countGarminSampleShape` は同期的な純粋関数で、データの存在と型を集計するだけ。**二度呼び出せば二度集計する**。ファイル名や設計書の「one-shot」は実装済みの制御を意味しない。GitHub CIの合成テストも複数プロセス間・複数Edge Runtimeインスタンス間の排他を証明しない。

## 実装を承認する前のハードゲート
1. **サーバ主体の有効化／失効**：ユーザーの明示承認に紐づく、対象・開始・絶対終了時刻・最大成功回数1の非公開設定。クライアントからフラグや時計を渡せない。
2. **原子的な一回限りの権利取得**：DBで`eligible -> claimed`を単一の条件付きUPDATE等で遷移させ、一つのインスタンスだけが成功。プロセス内の`let used`、envだけ、非排他SELECT→UPDATEは不可。これは**設計要件**であり、現環境にテーブル・RPCを作成しない。
3. **失効時刻の判定**：DB側で取得する現在時刻のみ使用。時刻境界のちょうど前/ちょうど後、処理が始まった後に失効した場合の結果書き込み拒否を明記。
4. **結果はフィールド別の件数と型だけ**。userId/garminUserId/activityId/summaryId/GPS/時刻実値/累積距離実値/心拍実値/Secret/token、受信URLを出力しない。保存先・権限・保管期間・ログローテーションを監査する。結果は低件数で個人が推測される可能性があるので『完全匿名』とは表現しない。
5. **従来のPushレスポンス・ACK・キュー・run保存非干渉**：検査失敗やDB接続障害がGarminへのHTTP 200/503と再試行動作を変えない。検査用通信が重くなるなら実装しない。先に合成HTTP integrationでDB失敗・失効・競合・悪意ある入力を試験。
6. **実データを扱う前にむせ独立監査とオーナーの明示承認**。PortaIへのログインや新しい実走は現時点で要求しない。待機する自然なGarminランがなければ未観測のまま停止する。
7. **追加費用ゼロ**：新規テーブル・RPC・ログの保持増加が無料/現行Pro枠内か確認できない限り本番No-Go。恒久的な監視・新規ログストリームは初期案に含めない。

## 必須シナリオ（本番変更前の独立テスト）
| ケース | 必須結果 |
| --- | --- |
| 同時に2通知、別Edge Runtime | 一方だけが権利を取得、結果は最大1回 |
| 既に消費済みの検査 | 二度目は検査せず既存受信だけ継続 |

## 調査結果・推奨
- 2026-11-12本番read-only集計ではInbox40件すべて`payload='{}'`。過去の生サンプルを掘り起こす案は不採用。
- 今日の追加合成負荷テストは最大100活動/20,000件の計数が性能の範囲内かを検査するだけで、複数サーバの排他や本番負荷を証明しない。
