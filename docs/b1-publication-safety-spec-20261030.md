# B-1 一般公開版：公開前の安全設計・受入条件（草案）
作成日：2026-10-30 / 状態：**仕様案・未実装・一般公開OFF**。
むせによるB-1非公開基盤の性能・失効監査合格とは別工程。非公開基盤のAtsuo最終承認と、一般公開の最終承認は別々に扱う。

## 目的・表示範囲
地域別に多くのランナーの努力を積み重ねて見せる。ただし個人の位置・ラン・距離を逆算可能にしない。候補データは非公開スキーマに保持し、公開用の専用読み取り口を検証完了まで設けない。既存の `region_rings_consent`（参加希望）は**正式公開同意ではない**。

## G1 正式公開同意（初期OFF）
- 同意前に「何を公開するか」「誰が見られるか」「更新頻度」「撤回方法」「撤回しても既に閲覧・保存された第三者コピーを完全回収できないこと」を日英で明示する。
- 地域・対象期間・集計指標、匿名加工の限界、本人のデータが集計に加わることを明記。個人名、活動日、GPS軌跡、個別距離は表示しない。
- 参加希望とは別の空欄チェック＋明示的な確定操作。画面読み込みや既存の参加希望ONから自動承諾しない。内容版数を固定し、同意日時・撤回日時を非公開に記録。説明版更新時は再同意を要するか審査する。
- 撤回操作は同じ画面から行えるようにし、確認後は直ちに再計算対象から除外する。UIは実装後に実機と独立監査を通す。

## G2 差分推測・少人数再識別防止
- `participant_count >= 5` は**必要条件にすぎず十分条件ではない**。同意者5人がいても、ある1人の増減や地域・期間の重なりで個別距離を推定し得る。
- 正式同意・参加希望の両方が有効な異なる実ユーザーが、対象セルへ実際に正距離を寄与したときだけ候補化。
- 設計時に、国/県/市区町村・年/月・総計と内訳の**差分**、公開の前後の差分、少人数の閾値近傍、参加/撤回の差分を攻撃者視点で検査する。
- 公開値の距離丸め、詳細度の引き上げ（地域統合・期間統合）、セル抑制、関連総計や隣接セルの同時抑制を組み合わせる。精密な距離・参加人数や更新直後の単独差分は外部に出さない。
- 丸め幅・最小参加人数・更新周期は監査用の合成データで決定する。**固定の5人閾値だけで公開許可しない**。継続公開の連続スナップショットからの復元攻撃もテストする。
- 生の集計候補、同意件数、秘匿対象のセル一覧をAPIやHTMLに混入させない。アクセス制御とRLS/権限、エラーレスポンスも検証する。

## G3 撤回・公開済みデータ・キャッシュ
- 撤回・ラン削除/修正・地域同期による失効で公開配信を止め、影響を受けた公開集計とキャッシュを無効化する。再集計前は旧集計を配らない（fail closed）。
- CDN、ブラウザ、共有URL、画像、SNSカード、検索エンジンキャッシュの更新・期限を定義する。第三者保存済みコピーは完全削除を保証しない旨を事前説明。
- 履歴スナップショットから個人の値が推測されるなら、当該セルだけでなく関連セルも非表示にする。キャッシュTTLと配信停止の確認試験を設ける。
- DBの公開フラグOFFを維持し、公開用API/ページ/ジョブの接続も安全審査まで無効のままとする。緊急停止手順・監視・障害復旧手順を決める。

## 公開前の必須受入テスト
1. 初期OFFの同意画面、明示操作、取消し、版数変更、日英文面の実機テスト。
2. 1〜4人、5人、人数入れ替え、本人だけに距離変化がある日、隣接地域・月・年/総計差分などの合成ケースで再識別耐性を審査。
3. 本番データを使わない公開キャッシュ失効・撤回・ジョブ競合・停止フラグのテスト。
4. 公開用権限・データ非露出・RLSの独立監査と、むせの正式判定。
5. Atsuoによる公開**個別**最終承認。未承認ならOFF継続。
