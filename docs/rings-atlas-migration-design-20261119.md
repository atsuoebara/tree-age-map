# Rings Atlas（リングスアトラス）移設設計 v0.1

状態：**設計監査用・未実装**／2026-11-19  
基準：main `b44305fff5e81e49ea7b92ddb5d4b9ff079bfe34`。関連PR #253（起動時の本人ラン件数表示・むせ最終監査合格、HEAD `85ca5b48`、未マージ）、#254（地図直前の期間別合計・むせ監査合格、HEAD `50851daf`、未マージ）。

## 目的と確定済みUX方針
- トップの地図には「選択した年・月の総距離／ラン数／走破地域数」をコンパクトに表示（#254）。地図そのものと現在の年・月選択は維持する。
- 地域別の詳細（国別、州・地域別、海外の市・郡・区別、日本の都道府県別、市町村別）は **Rings Atlas** という**別のページ**に集約する。表示場所だけを整理し、値・定義・操作・公開範囲を変えない。
- ラン一覧とカレンダーは将来の「マイラン」。右上の本人アカウント表示も別工程。既存のRings Territory／Rankingとは別機能であり混ぜない。
- 既存の詳細一覧はAtlasが同等機能を実証できるまでは**削除・非表示にしない**。

## 現行コードの確認済み依存
- `index.html` の `#appRoot > #mapPeriodControls` で `selectedYear` と `selectedMonth` を操作し、`renderSelectedData() -> buildSelectedStats() -> updateDashboard(stats)` で下部「あなたの記録」と地図を同時更新する。
- 現在のDOM（詳細）：`#countryHeading/#countryList`、`#regionSection/#regionList`、`#admin2Section/#admin2List`、`#prefectureSection/#prefectureList`、`#citySection/#cityList`。この順とIDを参照するJSが存在する。
- `updateCountryDashboard`、`updateRegionDashboard`、`updatePrefectureDashboard`、`updateDashboard` に表示ロジックが分散している。**`updateCountryDetailFlow(stats)` は既存DOMのセクションを append で再配置する。**一部の都道府県処理は地図上のハイライトレイヤーも更新する。このため「HTMLを単純に切り取って別ページへ貼る」は不可。
- 国内の走破地域は市町村数、海外はADM2数で、ADM2未分析の地域は `—` とする既存の判定を維持。国、都道府県、ADM1/ADM2の単位を混ぜたり、未解析の0件を捏造したりしない。
- クラウドのGPSルート込み全件取得は `fetchCloudRuns` の50件直列で、端末・接続状態によって遅い。Atlas移設で同じ重い取得をさらに重複させない設計が必要。

## 目標ページ（最終状態）
- `/rings-atlas.html`（仮のファイル名。公開は最終承認後のみ）。
- ログイン前：本人の地域走破データは一切表示しない。認証できない場合はログイン導線を出す。
- ログイン後：本人の表示期間（全期間／年／月）を明示し、必要に応じてその期間の地域別一覧を閲覧する。
- 初期表示：ロード状態を「確認中／前回データ／確定／失敗」で明確に区別し、取得前の「0地域」「0km」は出さない。
- トップからAtlasへのリンクはページ完成・検証後に設置し、現在選択した年・月を引き継ぐ場合は**期間値のみ**をURL等で引き継ぐ（ユーザーID、アクセストークン、ルート座標は引き継がない）。
- Atlasから地図へ戻る導線を提供し、戻った時も本人の年・月表示が自然につながること。

## 実装方式を決める前のゲート（現段階では未決）
1. **集計を共有する方式**を比較する。候補A：現行の純粋集計処理を共通JSモジュールへ安全に抽出し、トップとAtlasが同じ定義を使う。候補B：既存トップが作成した本人専用キャッシュの軽量集計結果をAtlasで再利用し、不足時だけ認証済みの読み出しを行う。前者は処理変更の回帰リスク、後者は未保存時／別端末／変更後の整合性に注意。計測前にどちらかを確定しない。
2. **データ取得・性能**。#253後の起動時UXを維持し、1,843件規模でもAtlas表示のためにroute込み50件×約37ページの二重ダウンロードをしない。将来の「routeなし軽量一覧＋必要時route後取得／再試行」改善と整合させる。取得回数・ペイロード・体感時間・端末キャッシュ有無を定量評価。
3. **認証・非公開**。RLSと本人セッションを必須とし、未認証・別アカウント・ログアウト・古いタブ・複数端末・Safari bfcacheで別人のキャッシュや表示が復活しないようにする。公開ランキング・公開許諾・写真公開名・NATIONSを変更しない。
4. **従来の地図との結合**。既存地域カードから地図上のハイライトや走行箇所へジャンプする操作は、別ページからどう機能を維持するか設計する。必要であればトップの同一操作を残す。移設による機能喪失禁止。
5. **多言語とPWA**。日英表示・375pxとiPad縦横・戻る／進む・古いSW・Build整合を検証。追加費用0円。
6. **負荷・エラー**。Safariのネットワーク例外 `Load failed` は発生源未特定であり、地域データと無関係と決めつけない。境界GeoJSONを二重ロードしない／失敗しても本人集計へ進めるかの改善を別途審査。
