# 保存済みランをカレンダーで探す（iPhone優先）独立監査依頼

- 2026-11-05
- 状態：未マージ、未公開、DB変更なし。既存「クラウドに保存したラン」一覧を残したままカレンダーを追加。
- 新規：index.html のみUI・ロジック追加、scripts/test-run-calendar.cjs（合成・静的回帰試験）。Journal記事は別途本人確認・公開承認が必要。

## ユーザー要望
1. 「ランニング記録」が他のボタンに埋もれて見つけにくい
2. 既存一覧を残し、画像例のようなカレンダーで過去のランを探したい
3. カレンダーには**日付と合計距離**を出し、同日に複数記録があればタップ先で全部開きたい
4. 2013年のNike+時代から最新まで年月を直接指定して探したい

## 内容
- 従来の `cloudRunsButton`、新しい順／古い順の `cloudRunsList` を削除・改変せず、取り込み操作の近くに目立つ `📅 カレンダーで探す` を追加
- クラウド記録パネル内の `📅 カレンダー ／ ☰ 従来の一覧` 切替。初期表示は従来の一覧のまま
- 年/月セレクトと前・次の月ボタン。閲覧可能な年はデータ内の年から現在までを候補として生成
- 保存済みクラウドデータ `cloudRows` をそのまま使用。日別合計距離を小数1桁kmで表示。数値不明なら `—`、同日に一部の距離が不明なら `+?` 注記
- 画面には「この月の保存済みラン X本・Ykm」を表示。**同じ `activity_date` に基づいた日別距離の合計 = 月表示合計**となるようにする。距離不明の行は件数に含め、距離への加算を行わず「距離不明あり」と明示
- **月間年輪の月集計と一致しない可能性がある**。カレンダーは `public.runs` の保存済み行（削除済みを除く）・`activity_date` 基準、月間年輪は地図構築済み `activities` の `Date` のローカル年月を使用しており、元データやGPS・重複・種目・日付の取得元が異なる場合、数値が食い違い得る。監査では母集団ごとの差を確認し、同じデータを同条件で集計した時のみ一致を期待する。無条件に「一致します」とは表示しない
- 同日の複数レコードは `n本` と表示し、選択後すべての活動名・距離を別々のボタンに表示
- 活動ボタンは既存の `focusCloudRun(row)` を呼び出し、従来の地図フォーカスを再利用
- `activity_date` の `YYYY-MM-DD` を厳密に日付検証し、UTC変換で前後日がずれないようにする
- ログイン本人の取得済みレコードだけ表示：`rrCalOwner` を **owner-scoped fetch成功時のみ更新**。異なるアカウントやログアウトでデータ表示を停止・消去
- 新しいサーバ呼び出し／DBスキーマ／RLS／記録の書き込み／外部公開なし。カレンダーは年輪節目の厳格なFIT/Stravaソース判定とは独立して、本人の保存済みラン全体を対象
- 主要ボタンは44px以上、狭い幅では日付とkmの折り返し表示を想定。日本語・英語切替ラベルを備える。カレンダー本文は切替/再表示時に最新の言語で構築
- 旧PR #40関連のiPhoneカード段差修正は**別PR #46で監査待ち**。このPRは段差修正を取り込まない

## むせに確認してほしいこと
1. カレンダーは全件保存済みの母集団と日付を正しく使用するか。削除済みや他人のランの混入なし
2. 年月指定で2013年から今日まで飛べるか。月をまたぐデータ、うるう年、同日複数ラン、距離不明、0kmの扱い
3. 保存済み一覧は従来どおり残り、並び替え・編集・地図への遷移が失われないか
4. 新しい入り口が既存のボタン・タップ領域・ログイン前画面を壊さないか
5. 初期ロード、キャッシュ・取得失敗、ログアウト・アカウント切替の漏洩がないか
6. 日本語・英語、320〜430pxの7列グリッドと長い数値で横はみ出さないか。操作しやすいか
7. 年輪の節A-4、Today、ランキング、GPS Art、インポートへ影響がないか

9. 合成テストと改修範囲に抜けがないか。マージしてよいか
