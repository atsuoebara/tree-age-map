# Phase 1-⑦ 第3弾：実在街路に沿う架空ラン・実装設計（2026-11-04）

## 判定
現在の幾何生成による37本デモ（index.html、コミット2f4a79a）は、技術動作は条件付き合格、見た目は未達。道路に一致しない線をさらに数式で曲げる方式は終了。ユーザー承認前に本番デモを置換しない。

## 実走感のある公開コースの候補
東京・隅田川テラス周辺を第一候補とする。個人の生活拠点でなく、河川敷と橋を核にする。
- 原型1（約3.5km）：東京都公園協会の隅田川テラス ショートコースを参考にした架空ルート（吾妻橋・蔵前橋・両国周辺）。
  https://www.tokyo-park.or.jp/water/waterbus/runwalk/course1.html
- 原型2（約10km）：同ロングコースの河川敷・橋周辺を参考にした架空ルート（浜町公園・中央大橋・勝鬨橋付近）。
  https://www.tokyo-park.or.jp/water/waterbus/runwalk/course2.html
- 原型3：同じ短距離コースの往復・分岐・一部周回のバリエーション。
- 原型4：両岸の歩道、道路上の交差点、橋の現実の接続に従う周回。
- 原型5：ロング走の行き先が存在し、そこで周回して戻るコース。
地理上の経路・歩行通行可否は、必ずOSMの歩行者向け経路データなどと地図で照合して確定すること。上記候補のランドマーク列は道順や通行可能性を保証しない。

## 必須の実装条件
1. 初回は3〜5本の原型のみを別プレビューで比較。最初から37本にしない。
2. 道路・歩道・橋・河川敷・公園入口の**実在の接続**を歩行者ルーティングなどで検証する。緑地・川・建物・線路を横切らない。自動車ルートだけでは不可。
3. 歩行者経路の折れ線座標を固定データに保存して描く。本番訪問者のブラウザから外部ルーティングAPIへアクセスしない。
4. 個人GPSは使わない。経路はルート探索により生成した架空のランニング計画であり、特定のランナーの履歴ではない。
5. 道路に実際に沿わせた場合、免責を日英とも「実在の街の道路・遊歩道を参考に作成した架空のサンプルです。実在ランナーの走行記録ではありません」に修正する。
6. ユーザーが認めた原型を後に年別10/12/15本へ展開。重なりを見せるには共通ルートと異なる道路への分岐を混ぜるが、線を道路からずらさない。
7. ALLではピンク2024・黄2025・水色2026の判別、凡例の色値一致、年別切替、aria-pressed、日英更新、遅延初期化を維持。
8. 本番の認証・ログイン後の地図・GPS取り込みには触れない。
9. iPhone Safari・ホーム画面アプリ・iPad実機で背景地図との一致、視認性、軽さを確認。
10. OSMデータの出典・帰属表示を維持。出典のライセンス確認を行う。

## 現時点のブロッカー
実在街路に沿う緯度・経度の折れ線をルーティングAPIから取得できていない。座標を推測で作ると同じ失敗を繰り返すため、**本番の index.html は変更しない**。歩行者経路の座標を取得・実地照合できてから、先に3〜5本の試作をレビューし、その後に公開を判断する。

## 独立監査の合格条件
道路/遊歩道と線の一致、走行可能性を示す根拠、3〜5本の固有性と自然さ、個人GPS不使用、コードの回帰なし、スマホの色視認性を確認。レビューで低評価なら公開を取り消す。
