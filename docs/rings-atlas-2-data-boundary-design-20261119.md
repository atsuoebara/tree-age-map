# Rings Atlas — Atlas-2 データ境界・同値性設計 v0.1

日付：2026-11-19　判定：**独立監査用の設計草案／実装・本番接続なし**

## 前提と停止線
- Atlas-0：PR #256 は設計監査合格。Atlas-1：PR #257 は静的・ローカルサーバ監査合格、**iPhone Safari 実機（bfcache、popstate、375/320px、iPad）は未確認**。
- PR #253（起動件数）最終監査合格、PR #254（選択期間の集計を地図上部に表示）監査合格。いずれもこの文書起草時点で未マージ。マージ順は **#253 → #254**。#256・#257も未マージ。
- 本設計を通しても **実認証・実API・本番DB・本番地図・既存トップ・ナビゲーションには一切触れない**。まず同値性・機能依存・性能の契約を監査する。

## 実コードで確認した依存
1. `index.html` の `getSelectedActivities()` が `selectedYear` / `selectedMonth` でローカル `activities` を絞り込み、`buildSelectedStats()` が国内市町村・都道府県・国・州/地域ADM1・海外ADM2の走行距離・ラン数を作成する。走行経路の交差判定・地理境界を使うため、単にサーバーの `distance_km` 合計や始点自治体で置換できない。
2. `updateDashboard(stats)` は同じ統計から総距離・ラン数・走破地域数を表示。走破地域数は **国内市町村 + 海外ADM2**（しきい値 0.01km 超）。海外ADM2未解析でゼロが根拠なしなら **`—`**。#254はこの結果を地図上部へ複写する設計。
3. `updateCountryDashboard` / `updatePrefectureDashboard` / `updateRegionDashboard` / `updateCountryDetailFlow` は既存DOMと Leaflet のハイライトに依存する。`updateCountryDetailFlow` はセクションをDOM間で append 移動する。Atlas専用ページへ純粋な計算関数のように切り出せない。
4. `fetchCloudRuns()` は `select=id,created_at,activity_date,name,distance_km,route,user_id,strava_id,source,started_at` を **50件ずつ直列**取得。1,843件では約37応答になり得る。取得した `route` が地理集計の根拠になる。
5. `loadCloudRowsCache()` は IndexedDB を `currentUser.id` で検索する。キャッシュは**前回のスナップショット**であり、認証完了・本人照合・鮮度確認・撤回／ログアウト後の消去の代替にはならない。

## Atlas-2で比較すべきデータ経路（現時点未選択）
**A：本人専用の集計スナップショット**
- トップ側で既存 `buildSelectedStats` を実行した後、地域別の軽量な統計だけを本人単位・版数付きで共有し、Atlas側で読み取り表示する案。
- メリット：Atlasによるルート全件再取得を回避できる可能性。重大リスク：トップ未起動・初回・別端末・取り込み後・削除/退会後・期間変更・仕様変更の鮮度、Safari bfcacheでの他人残像。専用スナップショットの保存先・容量・削除は別途承認が必要。
- **route、個別位置、本人ID、アクセストークンをURL・公開ストレージ・静的ページ内へ出さない。**

**B：単一の共有集計モジュール + 最小限の本人データ**
- `buildSelectedStats` の純粋部分のみ抽出しトップとAtlasで共通利用する案。Atlas側に必要な地理境界・経路をどう渡すかが未解決。最小項目だけでは現行の道路交差集計を再現できず、安易な代替不可。
- 同じGPSルートの再DL、境界GeoJSONの二重取得、地図への副作用、抽出による既存地図の破損を防止する構造と差分試験が前提。

**C：サーバー側本人限定集計**
- DB内の本人専用集計を読み出す案。現行アルゴリズムとの一致・RLS/権限・追加DB負荷・追加費用0円が証明されるまで候補扱いだけ。**今回DB/SQL新設は禁止**。

**選択条件**：安全性、差分一致、取得リクエスト数・転送サイズ、低速回線での初期表示、運用コストの実測を揃えてから、むせ監査 → Atsuo方式承認。Atlas-2では方式決定前に実運用コードに接続しない。

## 合成fixtureと同値ゲート
次のマトリクスを、既存アルゴリズムから**合成GPX/routeと人工境界**で算出する期待値を正本として固定し、新方式と1項目ずつ突合する。Atlas-1の架空カード値を正本と誤認しない。

|ケース|入力|必要な検査|
|---|---|---|
|P0|全期間（複数年・複数ラン）|5分類の距離とラン数、集計総数、選択期間ラベル|
|P1|特定年|対象年だけの距離・ラン数・都道府県等|
|P2|特定年月|当月だけを抽出。途中の月切替・同日複数ランを維持|
|Z0|**確定**0件|距離0・ラン数0・地域0を許可|
|U0|未取得・確認中|数字を捏造せず `—` / 読込中|
|U1|前回スナップショット|前回ラベルを明示、最新値を名乗らない|
|U2|読込失敗|0件へフォールバックしない、直前本人値の扱いを明示|
|ADM2|海外ADM1があるがADM2未解析|走破地域数 `—` を維持（ゼロ禁止）|
|BORDER|国境・県境・市区町村境界をまたぐルート|始点だけへ全距離を誤配賦しない|
|DUP|同日複数本・重複の対象と非対象|既存 `registerActivity` / 重複ルールとの同値|
|OWNER|A→ログアウト→B、戻る/進む、bfcache|Aの件数・地域・ルートがBに残存しない|
|FRESH|新規取込・削除・再同期・別端末|失効判定、キャッシュ反映と復旧、旧状態再出現なし|
|LANG|日英、日本語自治体・海外地名|架空地名の漢字残留、名称マッピング漏れを検知|
|WIDTH|320/375px、iPad縦横|横はみ出しなし、一覧操作可能|
|LINK|地域カードから地図へ戻る|元のハイライト・ズーム・期間選択と同等の操作（Atlas-3前に方式確定）|

合成状態では**個人の実GPSをテストデータに流用しない**。テスト中の期待値を更新して一致率を高く見せかけない。

## 安全・ライフサイクル
- ユーザー認証が完了しても自動で公開しない。本人セッション確認、RLS、owner一致をページ表示・データキャッシュ取得・再描画の各境界で守る。オーナー切替とログアウト時の表示破棄を先行。
- Safari `pageshow.persisted` からの復帰は必ず本人の新しい認証状態を再検証する。**Atlas-1の模擬ログアウトUIは認証実装ではない**。古いタブからの復帰も実際の認証検証が必要。
- 未認証、権限エラー、部分取得、タイムアウト、通信断では「0件」と確定せず、失敗を示す。**全ページ成功時のみ新しいスナップショットを確定・保存**。本人の既存スナップショットを空で上書きしない。
- 位置情報と自治体詳細は本人限定。Atlas専用ページを静的ホスティングしても実データはHTML/URLに埋めない。API権限変更・匿名集計公開・地図リンクへの識別子転送は別監査。
