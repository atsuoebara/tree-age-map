# B-1 一般公開版：合成データ差分攻撃の初回検証（2026-10-30）
状態：**攻撃デモ実施済み／防御設計未確定／公開OFF**

## 再現手順
`node docs/b1-privacy-attack-harness.js`

合成データのみ。実利用者・ラン情報・本番Supabaseは使用しない。現行の公開版製品コードを試したものではなく、**公開セルを5人以上でそのまま合計表示する仮定の危険性を示すテスト**。

## 実行結果
- S1: 同一地域で5→6人になり合計150→157kmを公開すると、追加1人の7kmを正確に差分推定できる。
- S2: 5人の子地域150kmと、同じ5人＋1人の親地域167kmを同時公開すると、差分17kmが漏れる。
- S3: 年間総計と月別合計から、残る月の差分13kmが判明する（算術的な組み合わせ攻撃の例）。
- S4: 6→5人の撤回前後を公開すると、撤回者の19kmが漏れる。
- S5: 10km単位の丸めだけでも、150→157kmの変化で公開値150→160kmとなり変化範囲が推定される。
- S6: 人数4人のセルが表示されないことは必要だが、S1〜S4を防げない。
- S7: 未承認ポリシー・公開OFFでは一切データを出さない fail-closed が必要。
- 7項目のデモをローカル実行で確認。これは再識別リスクの存在証明であって、防御策の安全性を証明するものではない。

## 公開方針の検討（数値は未確定）
候補A：国×年の粗い単位だけを、十分な人数・期間の大きさと固定更新間隔で公開する。
候補B：都道府県×年まで公開するが、国別総計との引き算、県間差分、時間差分、地域横断の重複ランナーを抑制する。
候補C：市区町村×月は当面公開対象外にする。人数が少ないうちは狭い粒度の公開を避ける。

いずれも無条件で安全ではない。公開時系列スナップショット、他セルとの連立推定、同意撤回の更新前後を含む合成ケースで、外部情報を持つ攻撃者にも耐えるかを確認する必要がある。
