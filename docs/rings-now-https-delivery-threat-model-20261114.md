# Rings Now：iPhone実FIT配信方式Aの脅威モデル（2026-11-14）

## 結論：方式Aは暫定第一候補、未承認
A：公開HTTPSのGitHub Pages上で配信するコードで、本人が選択したFITだけをiPhone Safari内で処理する方式を、iPhone優先・追加費用0円・PC不要の観点から暫定第一候補とする。実FIT利用／ページ公開の許可ではない。B：端末非公開環境はSafariのローカルモジュール等の制約検証が必要。C：認証付き限定公開は現在のGitHub Pages単独ではアクセス制限がなく、追加の運用要件が発生し得る。方式Aでも公開コードを誰でも閲覧でき、noindexや秘匿URLは認証ではない。

## 脅威モデルと検証条件
- 外部送信：FITバイナリ、GPS、心拍、タイムスタンプ、IDを送信／ログ化しない。fetchだけでなくフォーム、ナビゲーション、画像URL、外部読み込み、SWも評価する。CSPのconnect-src 'none'だけでは完全な証明にならない。
- コード改変：公開HTML/JSと監査済みコミットのバイト一致、全import先の独立レビュー、公開後の変更監視。
- HTTPキャッシュと古いタブ：CDN、SafariのHTTPキャッシュ、開いたままの旧タブ、SWを区別して停止・撤去手順を実証する。古いタブが消える保証はない。
- 画面復帰：非表示、pagehide、Safari bfcache復帰でファイル選択・同意・結果を失効。合成A〜Eは本人iPhone確認済みだが、実bfcacheの個別実測が報告されているとは扱わない。
- カレンダーと本人：本人がガチランを明示選択。同じ日・近い距離からFITを自動紐付けしない。開始時刻から8日＝691200秒、提供開始時刻はnullのため本番常時OFF。
- 保存と削除：FIT原本・GPS・心拍をDB、ログ、ブラウザ永続保存に入れない。JS参照破棄はOS内のメモリ消去保証ではない。
- 独立監査と本人承認：公開HTML、実FITを本人端末で利用すること、本番解析ONは別々の承認。実FITのGitHub・チャット・CI・スクリーンショット添付は禁止。
- 停止方法：本番コードの公開停止、旧タブの扱い、CDNキャッシュ残存、PR rollbackを別途検証する。

## 機械的な安全ゲート
新規 src/rings-now-https-delivery-evidence-gate.mjs は14個の証跡条件を列挙。いずれかが欠ければblocked、全部を真と申告してもrequires_explicit_final_authorizationとし、実FIT公開・読取・本番ONの許可フラグは常にfalse。証跡フラグを自己申告でtrueにできるため、**この結果は安全認証ではない**。実際のコード、通信経路、Safari実機をむせが独立監査する必要がある。
