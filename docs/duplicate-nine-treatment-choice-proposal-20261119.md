**Decision logic:** Both options fix source-based DISTANCE/NATIONS, but source-only soft delete cannot safely fix Territory Japan (deleted runs are actively reselected) or annual EXPLORE / Territory child readers. Physical delete removes all four identified FK child tables atomically with the parent, and eliminates Territory Japan's ability to reselect the removed parent, while avoiding the extra Today asynchronous event caused by `deleted_at` UPDATE. Thus physical delete currently has **fewer persistent downstream consistency hazards**. However its irreversibility increases the restore assurance requirement. A possible *third* path (soft-delete plus permanently audited producer filter changes and explicit full child cleanup) would require a separate code deployment and independent approval; it is not equivalent to existing soft delete.
