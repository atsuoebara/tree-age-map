# A-4「年輪の節」初期仕様案 v0.1（監査前・未承認）

作成: 2026-11-05
状態: **設計草案のみ**。アプリ機能・DB・公開設定は変更しない。

## 目的
走り続けた過程の「節目」を、本人だけが振り返れる小さな記念表示として残す。競争や順位ではなく、積み重ねの発見を重視する。

## 初期版（表示候補）
1. **ランニング100回目**：有効な保存済みランを開始日時（同時刻なら安定ID順）で並べた100件目。今後200回、300回への拡張は別途検討。
2. **初めての30km**：GPSと距離が有効な1ランの距離が30.000km以上となった最初の記録。複数の活動の合算では達成としない。
3. **初めての市町村**：走行ルートが地域境界を通過した最初の記録。ただし地域判定・境界データの精度や履歴の網羅性が不明なら初期リリース対象から外す。

## 厳密な判定前提
- 利用者本人の保存済みのランだけを対象にし、削除済み・無効・対象外種目は除外する。どのデータ属性が「有効」を示すか実装の確認後に確定する。
- 取り込み順ではなく**実際の走行日時**を基準にする。日時の欠損・タイムゾーンの扱いを確認するまでは「初めて」「100回目」を確定表示しない。
- 異なるサービス由来の同一ランの重複や、古いランの後日取り込みで記録が変わりうる。未確認の場合は「取り込まれた記録の範囲で」という注記を表示し、絶対的な生涯初記録と断定しない。
- 距離は既存の保存値を使う。30km閾値の丸め表示による誤判定を避ける（例: 29.995kmは未達）。
- 活動の修正・削除・追加で節目の結果は再計算する。共有済みの固定実績として扱わない。
- 他人のランニング記録、公開ランキング、B-1匿名集計は参照・変更しない。

## 初期UI
- ログイン本人向けの「年輪の節」プレビュー一覧から開始。未達成は「まだ記録されていません」と表示。
- 初期版では公開URL、共有画像、通知、自動投稿、SNS連携を実装しない。
- スマホ最優先。日本語・英語の案内を同時整備する。
- 一覧には節目の名称、対象日、距離または回数、判定対象の記録への導線、データ範囲の注意書きだけを載せる。

## 実装前の調査項目
1. 保存済みランのテーブル・主キー・開始日時・距離・種目・削除フラグを読み取り専用で確認。
2. 既存の重複判定と複数ソース由来の扱いを確認。
3. GPSルートと市町村境界との突合実装を確認。根拠が弱ければ地域節目は延期。
4. サンプルデータで、99/100/101回、29.999/30.000km、同時刻、未取得日時、削除、過去ラン追加、複数ソース重複を試験。
5. 実機表示、既存機能の回帰試験、むせの独立監査、運営者の最終承認を経て公開。

この文書は仕様確定や開発承認ではない。検証可能な最小1種類から実装することを推奨し、監査結果を踏まえて範囲を決める。
