# Rings Now：iPhoneでの合成検証を先行し、実FIT公開は独立承認（2026-11-14）

## 採用する配信方針
**当面は既存GitHub Pages HTTPSの「合成FIT専用ページ」だけをiPhone実機テストの公開入口として使用する。** 本人の実FITを選択できる新しい公開HTMLを追加しない。GitHub Pagesは認証制の非公開配信ではなく、URLを秘密にする方式やnoindexでは保護にならない。従って、今の公開サイトで実FITの試験を始めたとは言わない。

将来の実FITの候補方式は、(A) **公開HTTPS静的ページ＋端末内解析**（公開されるコードの変更と外部経路を別途監査し、本人が公開範囲を個別承認する必要あり）、(B) **端末上の非公開環境**（iPhone Safariのローカルファイル／モジュール起点やセキュリティ制約を実機検証しなければ採用できない）、(C) **認証された限定公開環境**（現在のGitHub Pages単独では実現せず、新しい費用・保守・認証問題が発生し得る）。現段階の判断は「実FIT用は未決定」。追加費用0円とiPhone優先を守る。PR #109 PC必須ZIP案はHOLD。

## 今回の安全な前進
新規 `src/rings-now-iphone-isolated-handoff.mjs` は、監査済み #118 `createRingsNowIphoneSessionBoundary` と #115 `createRingsNowPrivateFitController`を**隔離された合成テストでだけ**結ぶ。将来の呼び出し元が本人／選択行／ガチラン／開始時刻を直接渡す。ページを離れる、`pageshow.persisted`で戻る、タブが非表示になると、選択失効だけでなく**ファイル選択・二重確認・表示結果を消す**。`invalidate()` はログアウト／カレンダー日付変更／ラン削除／ルート離脱時に呼び出し元が実行する必要がある。未接続の本番アプリが自動的に認証や画面失効を保証するわけではない。

- 実Garmin FITファイル、アカウント情報、GPS、心拍、ユーザーIDをテストに使わず、全て合成。
- FITの記録とカレンダー行の一致は**自動推測しない**。境界の生存判定は同一ランであることの証明ではない。
- テストだけが架空の`featureStartedAtMs`を渡す。本番は`RR_IMA_WO_SHIROU_CALENDAR_ENTRY_ENABLED=false`、`RR_IMA_WO_SHIROU_FEATURE_STARTED_AT_MS=null`、よって解析不可。
- 参考候補は「未認証」「保存不可」。注意書き：**信号待ちやトイレ休憩、自動ポーズなどの影響により、正しく分析できない場合があります。**
- UI破棄時に参照が消えることと、Safari/OSがバイナリを物理消去することは同義ではない。
- 旧実FIT試作ページは#117本番監査合格で案内ページに切替済み。本PRでは変更しない。
- `index.html`、`sw.js`、DB、公開HTML、既存FIT解析モジュール、iPhone合成専用ページを変更しない。

## 本PRの監査境界
新規4ファイル（隔離接続モジュール・合成テスト・この文書・CI）だけ。ネットワーク、保存、ファイル解析処理の新規実装もなし。iPhone Safari実機で本モジュールを実行した証拠はなく、合成Nodeテストの成功を実機合格や実FIT使用許可へ読み替えない。

## 次の別承認
次のPRで新しい公開HTMLを検討するなら、公開内容は**合成FIT限定**とし、ファイル選択から実FITを開けないことを実データ不要の試験で担保する。実FITを扱える画面を新規配信すること、そのページで本人の実FITを読むこと、本番Rings Now ONは**それぞれ独立監査と本人の明示承認を経て別々に行う**。
