# A-4 第5弾 P1・Nike+ TCX種目証拠の端末内調査（独立監査依頼）

日付：2026-11-05。**未マージ・未公開・DB操作なし。** むせのPR #36設計監査で許可された「P1の証拠評価の調査」のみ。

## 目的
Nike+時代の元TCXファイルが手元に残っている場合、ファイル中の `Activity Sport` を**ブラウザ内だけで**確認する。現行A-4に登録した行と照合・認定は**まだ行わない**。

## 変更
新規単独ページ `a4-tcx-evidence-local.html` のみ。メインのindex、A-4計算、DB、保存済みラン、認証、同期、ランキング、公開共有などには変更なし。ページへのサイト内導線も追加しない。監査後に導線を決める。

## 現状のP1の可否
- ローカルファイル選択（.tcx/.xml、最大30ファイル、1件8MB・合計50MBの上限）
- DOMParser `application/xml` でファイルごとに解析。TrainingCenterDatabase直下であることとActivity要素の存在を検査
- **ActivityのSport属性だけを種目の証拠**として扱い、Running明記／他種目／不明に分ける
- 同一ファイル内に複数Activityがあれば活動単位の件数として計算。ファイルごとに3区分の件数を表示
- ファイル名・ID・日付・距離・GPS・ルート・元XML内容は画面に表示しない
- `file.text()` と `DOMParser`、DOMへの `textContent` を使用し、ネットワーク転送・fetch・localStorage・sessionStorage・indexedDB・Cookie・新規DB通信なし
- meta CSPで `connect-src 'none'`、外部JS/画像/フォント禁止。robots `noindex`
- 結果はメモリと画面だけ。消去ボタンで画面結果とファイル選択を消去
- ZIPは対象外。原本の紐付け、一意照合、本人確認、認定保存・認定反映は実装していない

## 注意事項
- `Sport=Running` は元ファイル内の種目申告という証拠であり、DB上の328行との同一性を保証するものではない
- TCXが `Sport` を省略していたら「種目不明」。Nike+という年代・ファイル名だけでラン認定しない
- ファイルに虚偽のSport記載があればそれ自体は検出できない
- 調査を行う本人以外に生ファイルを渡したり、スクリーンショットで軌跡や個人情報を公開したりしない

## むせの独立監査項目
1. ブラウザローカル解析のみで外部通信・DB書き込み・ログ保存がないこと
2. Sport属性のRunning/それ以外/欠損/空値/大小文字/複数Activityの判定
3. 不正XML、TCXではないXML、超大容量、非TCX拡張子が安全に拒否されること
4. DOMParserや結果描画のXSS/外部リソースへのアクセス経路がないか
5. 1ファイルに複数Activityがあった場合、**ファイル件数ではなく活動件数**と明示できているか
6. スマホ幅での折り返し、iOS SafariのFile APIとDOMParserの互換性
7. P0・既存の初30km・100/500/1000回目に影響ゼロ、認定を勝手にしないこと
8. 本番配信可否と、必要なら追加すべき小さな修正・試験を提示

本PRは研究用の原本検査であり、**DBとの突合・認定対象拡大の開始条件を満たすものではない**。P2の本人確認の永続保存やP3の反映は別監査・明示承認必須。
