## 変更理由
ユーザーより「アプリだったらカレンダーをスクロールみたいに左右に直感的に動かせるんだろうね」と提案あり。開発担当がジャーナルの執筆を先に進めてしまい実装を失念したため、別PRで追加する。

## 変更点
1. `rrRunCalendarDays`（7列の日付グリッド）のみにネイティブ `touchstart`、`touchend`、`touchcancel` を付与。カレンダー外のページ/ヘッダー/年・月セレクトは対象外。
2. 指を左へ動かす（deltaXが負）：翌月。右へ動かす：前月。月移動処理は `rrCalShiftMonth` に一本化して、従来の左右矢印も同じ関数で動かす。
3. スワイプ受理は `|deltaX| >= 55px` かつ `|deltaX| > 1.4×|deltaY|`。短いタップや縦方向のページスクロールは妨げない。
4. 受理したスワイプだけ `touchend.preventDefault()`（passive:false）して、合成クリックで日付が同時に開かないようにする。touchstartとtouchcancelはpassive:true。
5. 複数指のタッチ、未ログイン、対象所有者以外、一覧モードではスワイプを行わない。
6. 月を変更したら選択済み日付を解除し、カレンダーを再描画。年越しに対応。
7. 既存の一覧タブ、年間セレクト、月セレクト、距離集計、記録から地図への遷移、Today、A-4、言語切替には触れない。

2. タッチキャンセル、複数指、所有者切替、非カレンダーモードの動作。
3. 左へ翌月／右へ前月の方向、12月↔1月の年越し、選択日のクリア。
4. `touchend.preventDefault` で日付ボタンの余計なclickを発生させないか。長押し等への影響。
5. もとの左右矢印・年/月セレクト・同日複数ラン・記録詳細が正常か。
6. iPhone画面320〜430pxで自然なスワイプになるか。必要なら実機での残条件を具体化する。
