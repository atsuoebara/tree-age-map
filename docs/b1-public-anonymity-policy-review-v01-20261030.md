# B-1 公開匿名集計ポリシー・設計監査依頼 v0.1
2026-10-30 / **提案段階・安全性未証明・同意受付OFF・一般公開OFF**

## 方針の選択案
**初回リリース候補は「国×完了年」だけに絞り、月・都道府県・市区町村・国別総計と地域内訳の同時公開はしない。**
国別であっても人数の集中、外部から既知の走者、年度間比較により推測は可能なので、この選択のみで匿名性を保証するものではない。一定の安全性が証明できないなら国別合計距離も表示せず、空の案内ページだけにとどめる。

## 具体的な提案（確定値ではない）
- 公開候補セル：一つの国コード×確定した暦年。進行中の年は公開しない。地域をまたぐランは既存の検証済み配賦ロジックを使うが、本人の行動履歴を公表しない。
- 表示候補：**丸めた合計距離だけ**。参加人数の具体値、GPS軌跡、最新更新時刻、最近増えた距離、順位変動、直近の月別内訳、参加者一覧、割合、基礎候補表は表示しない。
- 抑制条件の検討：最小寄与人数は既存の5人チェックを下回らず、もっと厳しい閾値を合成攻撃で決定する。いずれも人数のみでは不十分。最大寄与者/上位少人数が合計の大部分を占めるセルは抑制対象（寄与の支配性）。同じユーザーが関連セルに重複寄与する場合は差分攻撃を別途評価。
- 丸め：切り上げ・四捨五入のみでは前後差分を防げない。候補として粗い固定刻みを検証するが、刻み幅を固定する前に攻撃成功率と表示価値を比べる。
- 公開更新：進行中の年・日次/月次更新は禁止。**確定年の単一公開スナップショットを原則**とし、同じ年の更新・再公開は原則禁止（撤回・削除・誤集計等の例外では配信停止を先行）。公開した旧版と新版を外部から比較できることを前提に、必要ならそのセルを恒久非表示にする。
- 国境・集計期間・参加者の重複による差分攻撃、年度切替、出入り、単一走者支配の仮想データを検証。関連セルを組み合わせて残差が判明するなら該当セルをまとめて抑制する。

## 同意撤回とキャッシュの停止優先
1. 正式同意の撤回を受信した時点で、サーバー側の公開世代を無効化する。古い公開世代はAPIで再提供しない。
2. 集計候補を失効させ、人数・寄与支配・差分安全条件を再評価する。
3. 安全が証明できなければ該当国×年を非表示のままにする。公開済み数値との比較で情報が漏れる場合は、安易に新数値へ更新しない。
4. 本人への完了表示は実装で保証できる停止範囲と時間に合わせる。CDN/ブラウザ/検索/SNS/保存スクショの消去は保証できない。公開APIに `no-store` 等を付けても過去の第三者コピーは消えない。
5. 公開フラグがOFF、候補dirty、世代不一致、同意版不一致、監査未承認のときは常に返却値なし（fail closed）。

## 攻撃テスト計画（合成データのみ）
T1 参加人数4、5、10、20、100人の境界と寄与偏り、T2 新規1人の参加と撤回、T3 複数年度の同じ走者、T4 一国だけで走る既知参加者、T5 国別と大陸/全世界の上位総計差、T6 丸め境界とスナップショット差分、T7 同時撤回/再同意/集計ジョブ競合、T8 リクエスト連打/ブラウザキャッシュ/公開停止中のAPI照会、T9 閲覧者が一部走者の個人記録を外部情報として既知の場合。
**判定基準案**：個人寄与値が単一または複数公開セルの差分から一意復元されるケースは不合格。単に一意復元されないだけでは十分でなく、狭い区間に限定できるケースも個別精査。完全な匿名性は保証できないので残余リスクと公開価値を判断し、許容できなければ数値公開しない。

## むせへの設計監査依頼
1. 国×完了年だけに絞る初期案は、他の粒度を公開するより現実的か。国単位でも避けられないリスクは何か。
2. 閾値・寄与支配・距離丸め・スナップショット更新方針について、必要条件と危険な抜け道を指摘してほしい。具体的な閾値は**監査時点では確定しない**。
3. 撤回した時点の停止、古いスナップショット差分とキャッシュ対策が両立する最低要件を確認してほしい。
4. 公開前にユーザーへ示す最終同意文面に、国×完了年・匿名性の限界・撤回の反映タイミングをどう表現すべきか。
5. 数値集計の公開を断念して非数値案内だけにする停止判断の条件を提案してほしい。

**実装・公開・同意受付は行わない。監査後に具体数値と受入試験を確定する。**
