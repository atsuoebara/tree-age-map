# Rings Now：iPhone端末内FIT試験環境・セッション失効境界（隔離） — 2026-11-14

## このPRでできること／できないこと
旧実FIT試作ページの停止はPR #117で本番独立監査合格・正式完了。iPhone合成FIT専用ページは従来どおり合成294-byteのみ許可。PR #114の実FIT入力ゲートとPR #115のUI制御は隔離実装であり、**本番FIT利用／公開配信の許可を意味しない**。

本PRはiPhone Safariの**ログアウト、日付／行の選択変更、8日失効、タブ非表示、pagehide、bfcache復帰**で、将来のローカル解析UIを安全に止めるための「生存確認コールバック」を作る。実FITを開かず、公開用HTML、SDK、DB、SW、ホーム画面は変更しない。確認は合成のユーザーID・行・時刻だけ。mainに入れても公開ページから呼ばれない。

## 既存部品をどう繋ぐか（設計のみ）
将来の本人向け画面は既存カレンダーで選んだ**1行**を読み、`createRingsNowIphoneSessionBoundary`へユーザーID、選択行、明示的ガチラン選択トークン、現在時刻、`featureStartedAtMs`を渡す。さらにこの境界の`isContextCurrent`を、PR #115のUIコントローラが求める同名のコールバックとして渡す。

`isContextCurrent()`は都度、選択した行のid／user_id／started_at／activity_dateとセッションの本人ID、明示的な選択トークン、削除状態を検証する。**FITの日時・距離で保存済みランに自動紐付けしない**。経過時間ルールは既存カレンダーアダプタを再使用し、`started_at`を基準に8日＝691200秒の端点を1ミリ秒単位で判定する。境界は**選択したランが条件内であるかの確認のみ**を行い、実FITと当該ランが同じ記録であることの証明も、正式診断の許可も行わない。

`featureStartedAtMs`の**本番値はnull**。このままでは常にfalse。合成テストだけが明示的な仮の開始時刻を与える。日時不明・本人不一致・セッション切替はfail-closed。

iPhone Safariの`pagehide`、戻る／進むによるbfcache復帰（`pageshow.persisted`）、`visibilitychange`でhiddenになったら、選択を永久に無効化する。利用再開には**新規にカレンダー行を選び直す**。既存のUIコントローラを接続する際、`invalidate`／`destroy`と同時に呼び出し側の明示的な処理が必要。ファイル本体のブラウザ内部メモリ消去や、OSによる旧タブ破棄を保証するものではない。

## 配信・iPhone試験の段階
1. **本PR**：隔離したセッション境界の実装と合成ID・日時の自動テストだけ。新しい公開ページも実FIT入力も一切なし。
2. **次の監査**：iPhoneで実行する試験環境の配信方法を決める。公開GitHub PagesではURLを秘密にできず、CSP／SW／HTTPキャッシュの限界を再確認する。実FITのバイナリ／GPS／心拍／個人IDをGithub、チャット、ログ、CIに渡さない。
3. **別途本人承認**：実FITを端末内で扱う試験環境が独立監査合格した後に、本人が**公開HTMLの是非、実FIT使用、正式解析ONを個別に承認**。現在は全て未承認。
4. PC専用ローカル起動（PR #109）はHOLDのまま。iPhone最優先・追加費用0円。

## 既存仕様
Rings Now＝NOW（今）× KNOW（知る）。ユーザー自身がカレンダーで「ガチラン」を選ぶ。「1km解析」は手段、機能名とは別。欠損や信号待ちを無理に補完せず、**信号待ちやトイレ休憩、自動ポーズなどの影響により、正しく分析できない場合があります。** を今後の表示で継承する。
