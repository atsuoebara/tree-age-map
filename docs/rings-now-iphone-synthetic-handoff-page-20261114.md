# PR #120：iPhone合成FIT専用連携ページの公開前レビュー（2026-11-14）

## 目的と公開状態
PR #119で独立監査合格・main統合済みの隔離UI/セッション結合を、本人のiPhoneで**合成294バイトだけ**操作・失効検証するための公開候補画面をDraft PRに追加した。

**PRをmainへマージするまでは新URLは公開しない。** GitHub Pagesは公開HTTPSであり、noindex・URL非告知は非公開アクセス制御ではない。マージ後は誰でもHTMLとJavaScriptを閲覧できるので、その前に独立監査＋本人承認が必須。

## 実FITを拒否する順序
- 既存の2026-11-14合成専用ページで検証済みの架空FITデータを**バイト単位で再利用**。サイズ294、固定ファイル名`rings-now-synthetic-5km.fit`、SHA-256 `24c29cacc088ee2cb2a43f82402d88dfd222a389da98f7b37704e87ba64163aa`。
- 新規 `src/rings-now-iphone-synthetic-inspector.mjs` が **元ファイルのバイナリがこのSHAと一致するまで既存パーサーを一切呼ばない**。一致しないFITは解析せず遮断する。検証通過後は検証済み合成バイトの別コピーだけを既存 `inspectRingsNowPrivateFit` に渡す。
- ハッシュ検証では選択したファイルのバイナリを端末メモリへ読み込む。ただし**不一致ファイルの解析は行わない**。OS/ブラウザによる一時メモリの物理消去は保証できない。
- 本番の`RR_IMA_WO_SHIROU_CALENDAR_ENTRY_ENABLED=false`、`RR_IMA_WO_SHIROU_FEATURE_STARTED_AT_MS=null`は維持。公開候補画面は**架空ユーザー／架空カレンダー行／現在時刻から作る架空選択**に、テストだけの仮`featureStartedAtMs`を渡す。実アカウントや本番カレンダーとは接続しない。
- 本ページの二つのチェックは、**架空テストデータへの確認**であり、本物のガチラン指定でも利用者認証でもない。
- 読取出力は`reference_only_unverified`で、正式な診断／保存を許可しない。注意書きは「信号待ちやトイレ休憩、自動ポーズなどの影響により、正しく分析できない場合があります。」で固定。

## iPhone Safari画面離脱
PR #119の`createRingsNowIphoneIsolatedHandoff`を実際に呼び、既存のページ非表示、`pagehide`、bfcache復帰、確認取消の失効を動作させる。模擬離脱ボタンでも同じ`invalidate()`を呼ぶ。再試行はページ再読込と架空データ再選択が必要。iPhone端末での実測は**マージ後、本人が実機で確認する別作業**。Nodeの模擬イベントテストだけでSafari実機合格とは言わない。

## セキュリティと残課題
- 新HTMLにはCSP（`default-src 'none'`、`script-src 'self' 'unsafe-inline'`、`connect-src 'none'`等）、noindex、外部通信API不使用を明記。HTTPSを配信する公開GitHub Pagesのコードは誰でも読める。CSP単独の保護保証や絶対に通信が不可能との断言はしない。iPhoneのブラウザネットワーク確認は別途必要。
- 本PRは **新規4ファイル**（合成専用HTML、ハッシュ検証アダプター、Nodeテスト、文書、CI）ではなく、正しくは**新規5ファイル**。既存画面・SW・DB・SDK・カレンダーコードは一切変更しない。
- 本番解析をONにすること、実Garmin FITを解析すること、実FIT画面の公開方式決定は**いずれも未承認**。
- 合成のバイナリにもSHA衝突の理論上の可能性はあるが、既知の固定ファイルの同一性検証として使う。実FITや個人ランデータはGitHub、チャット、CI、証跡へアップロードしない。
- PR #109 PC ZIP方式はHOLD。
