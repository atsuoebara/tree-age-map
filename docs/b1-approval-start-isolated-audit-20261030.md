## 新規コードの狙い
1. 非公開の `region_rings_release_decision` に国×年×世代×規約版×丸め値×確定日×匿名性/同意審査参照×承認者を不変保存。承認関数は審査を自分で生成しない。
2. `b1_private_approve_year` はグローバル状態行をFOR UPDATEでロックし、版・世代・暦年完了・締め・審査承認・既存dirty解除を確認。行を非公開スナップショットに挿入し、同一処理で台帳へapproveを追記。**配信ONはしない**。
3. `b1_private_start` はグローバル状態をロックし、旧dirty=false・同世代同規約の承認済みの行と対応審査記録を確認。初めて配信ONし、同一処理で各セルのstart台帳行を追記。旧ゲートのpublication_enabledはOFFのままでよい。
4. 元の `b1_private_stop` により停止・世代増加・台帳stopを一処理とし、古い世代の審査では再開不可。
5. 公開ロールへの実行・テーブル権限は付与しない。リリース決定台帳のUPDATE/DELETE/TRUNCATEも拒否。

## 合成データ試験
- 事前の審査レコードがない時、approve/startが拒否される。
- 審査済みレコードが存在するとapproveが通るが、開始前は数値が一切読めない。
- startすると該当の丸め値だけが内部関数で読め、台帳に開始が1回残る。
- stopで読めなくなり、同じ審査記録・旧世代でstart/approveができない。
- 前回の旧dirty独立セル試験は、事前に見えることを検査してから旧dirtyだけを立てる。
