# 「今を知ろう」FIT品質検証マトリクス（2026-11-14）

## 目的と実行範囲
PR #106 までの隔離基盤は監査済み・main統合。今後、実Garmin FITを扱う前に**既存デコーダからの候補区間と診断フラグ**の再現性を合成FITバイナリで検査する。テストはランナーの実ファイルを使用せず、既存リポジトリのFIT SDK Encoderで生成した合成データのみを扱う。

## テストケースと期待
1. 継続走：1kmあたりの時計経過時間を候補として計算。ただし品質認定・分析許可なし。
2. 信号／トイレに似た停止：累積距離のplateauとtimer stop/startを含む。停止により**一律除外しない**。時間は差し引かず注意すべきフラグを保持。停止の真の原因を断定しない。
3. 長い記録間隔：長時間のレコードギャップをフラグ化。データ欠損を推測補間して品質認定しない。
4. 開始直後の点欠損：走行開始が記録の最初の点と一致しない場合、未知の時間を捏造せず拒否。これは『信号停止で一律除外』とは異なるデータ品質の理由。
5. セッション総距離とレコード距離が不一致：フラグを付け、数値修復・品質認定を行わない。

## 既存決定との整合
ユーザー合意の用語：表示名『今を知ろう』、内部『1km解析』、対象『本人が選ぶガチラン』。走行開始8日以内（691200秒ちょうど有効、超過失効）、過去遡及なし。停止のあるランを自動除外しない。停止を含む時計上の経過時間を利用し、自動ポーズ等で正確に解析できない場合は『信号待ちやトイレ休憩、自動ポーズなどの影響により、正しく分析できない場合があります。』と説明する。停止時間の勝手な除外・補正や、存在しない区間数値の捏造禁止。2026-11-12以前の停止一律排除案は不採用。

## 限界と未解決
**これは実Garmin FITを使ったテストではない。** Encoder生成の単純な合成データで挙動を確認するのみ。実Garmin機種固有のauto-pause、停止中に記録点自体が欠落する形式、session時刻ズレ、記録点間の飛び方、クラウドrun IDとの一致を証明しない。既存 `reviewSingleUserFitBuffer` は候補を `candidate_unverified` かつ `analysisAllowed:false` と返す。

実データ確認では本人が選んだFITのみを端末内で読み、PII・GPS・生データをGitHubや解析サーバに送らないこと。実データが取得できないまま『Garmin品質検証合格』とは宣言しない。
