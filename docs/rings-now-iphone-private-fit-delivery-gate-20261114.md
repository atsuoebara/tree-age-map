# Rings Now：iPhone実FIT画面の安全な配信ゲート（2026-11-14）

## 結論 — 現時点は実FITの新規配信・利用を禁止
PR #112で本人のiPhone上の**合成FIT**表示を確認し、#113で記録済み。#114の入力ゲート、#115のUI制御は独立監査合格・本人承認を経てmainへ統合済み。ただし**実FITをiPhoneで試したことはなく、その操作画面も許可していない**。

次の段階を「配信方式とプライバシー境界の監査」とする。**このPR自体は文書＋静的検査＋CIだけ**。新しいHTML、公開URL、実FIT受付、クラウドへのデータ送信、DBの変更、Service Workerの変更は行わない。

## 既存コードで実際に確認できること
- `index.html` は `RR_IMA_WO_SHIROU_CALENDAR_ENTRY_ENABLED=false`、`RR_IMA_WO_SHIROU_FEATURE_STARTED_AT_MS=null`。カレンダー入口は実行不能。
- `sw.js` の現在の`fetch`ハンドラは、公開アイコンのみCacheStorageに保存。ホーム画面はnetwork-firstで、失敗時はofflineページ。**その他のページ・JSモジュールはSWのrespondWith対象ではなく、SW自身によるキャッシュはされない**。
- `previews/rings-now-iphone-synthetic-only-20261114.html` は実FITを受け付けない（合成294バイト、ファイル名、SHA-256一致をデコード前に要求）。既存HTMLは変更しない。
- `src/rings-now-private-fit-input-gate.mjs` は本人・ガチランの二重確認、サイズ、選択失効、未認証出力だけを許す。ファイルの中身を通信・保存しない。
- `src/rings-now-private-fit-ui-controller.mjs` は公開画面からimportされない。呼出側が所有者・カレンダー行・日付・アプリ内セッションの整合を保持する必要がある。

これらは**コード上の既知の範囲**であって、SafariのHTTPキャッシュ、ブラウザ拡張・端末の管理機能、実際の通信トレース、外部依存の完全性まで証明しない。

## 注意：公開ディレクトリ内の旧開発用HTML
`previews/ima-wo-shirou-fit-local-file-draft-20261113.html` という以前の本人FITローカル試作ページがリポジトリに存在する。**GitHub Pagesで配信され得るHTMLは「未公開」とラベル表示してもアクセス制限にならない**。本工程ではこれを安全な実FITテスト用URLとして案内・使用しない。公開導線を作る前に、この旧HTMLの配信状況、必要な撤去・移管と閲覧時のリスクを独立に監査する。

## 配信方式の判断
1. 本人のiPhone優先。PC必須のローカルサーバ方式（PR #109）はHOLDのまま。iPhone内の標準ファイルピッカーを活用する。
2. GitHub Pages等の**公開HTTPS静的ページ**は、アクセス可能な全員へHTML・JSを配信する。秘匿URL・noindex・利用者のチェックボックスは認証ではない。ページから実FITを端末内で選択させる場合は、第三者による改変・同一オリジンのコード・将来の配信変更を含むリスク評価と本人の個別承認が必要。公開ページへの実FITファイル**アップロードは不可**。
3. 静的コードの配信と実FITの送信は別。**端末内解析**として承認するには、依存JSを含めてネットワーク・DOM・ストレージの動線を完全追跡し、実FITのバイナリやメタデータが通信／ログ／テレメトリに流れないことを検査する。CSPの`connect-src 'none'`は有益だが**それだけで十分ではない**（ナビゲーション、外部リソース、フォーム、SW、ブラウザ環境の各経路も検査対象）。
4. iPhone向けの独立試験ページを将来用意する場合、その試験ページをGitHub Pagesに載せる行為自体が**公開**となる。合成専用プレビューの公開承認を実FITテストに転用しない。
5. 公開HTMLではブラウザのHTTPキャッシュも別途検討する。GitHub Pagesの任意のキャッシュ制御ヘッダーに依存できない点も設計要件とする。アップロードゼロを確認してからデータの機密性を説明する。
6. 選択したFITとカレンダーの同一性を`同じ日＋距離近似`だけで判定しない。実FITから開始時刻を推測して既存カレンダー行へ自動紐付けしない。8日＝691200秒、正式な提供開始時刻は未設定。過去の11/3ぐんまFITは本番期限外で隔離検証のみ候補。
7. ログアウト、ファイル変更、日付変更、タブ非表示・破棄でUI制御を失効させる。Safariでの戻る・ページ復帰（bfcache）も検査する。メモリ上の結果を再表示しないことを確認する。
8. iPhone実機の実FIT検証を始める前に、**むせ独立監査で配信方式と実FITの端末内処理経路を合格判定し、Atsuo本人が新たに明示承認**する。ファイル原本・心拍・GPS・IDをチャット、GitHub、テスト証跡へ添付しない。
