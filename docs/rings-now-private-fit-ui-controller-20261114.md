# Rings Now iPhone本人FIT選択UIコントローラ — 2026-11-14

## 目的と境界
PR #114で独立監査合格・本人承認を経て統合したFIT入力ゲートを再利用し、**iPhoneからファイルを選ぶときのUI制御**を独立モジュールとして実装する。ここでの「UI」は操作イベントと表示処理であり、実際に公開されたHTML画面ではない。**実FITを開いたことは一度もない**。テストは完全に合成FITのみ。

新規 `src/rings-now-private-fit-ui-controller.mjs` は既存公開画面・カレンダーから一切importされない。カレンダーの起動機能はOFF、ロールアウト開始時刻はnull。ソースコード自体がGitHub Pagesから公開され得ることは認識しており、プライバシー保護は「秘密のURL」ではなく**操作禁止・非送信・非保存・未接続**に基づく。

## 挙動
- 依存するDOM要素（FIT選択input、本人チェック、ガチランチェック、確認、キャンセル、状態、ラップ）を**呼び出し元が明示**して渡す。新しい公開HTML・ページは追加しない。
- ファイルを選び直したら確認チェックを解除し、前の候補結果を消す。二重確認前の読み取りなし。途中キャンセル・ログアウト・日付変更で`invalidate()`を呼べる。
- `isContextCurrent`（本人・日付・選択ラン・ログアウトの生存判定）は必須。読み取り前後に`inspectRingsNowPrivateFit`の`isSelectionCurrent`が呼び出される。古い非同期結果は描画しない。
- `destroy()`はイベントリスナーを解除し、表示とファイル選択値を消す。キャンセル後・画面破棄後の古いコールバックが画面を書き換えない。
- 既存ゲートが`reference_only_unverified`かつ4つの禁止フラグfalseを返した場合だけ参考ラップをDOMの`textContent`で表示。`innerHTML`や生FIT・GPS・心拍・時刻・ユーザーIDを画面に出さない。
- 正式警告文：`信号待ちやトイレ休憩、自動ポーズなどの影響により、正しく分析できない場合があります。`。
- FITと保存済みランを**距離や日付の近さで自動紐付けしない**。個別カレンダー行の所有者と8日期限は別のゲートで厳密に確認しない限り本番解析不可。
- 既存の合成専用ページ`previews/rings-now-iphone-synthetic-only-20261114.html`は一切変えない。実FITの公開入力画面は別途配信・SW・CSP・認証・端末内処理の監査を要する。

## テストと未検証
- 合成5km・27分で期待する5区間表示、チェック無し拒否、遅延ファイル読み出し中のキャンセル、選び直し、ログアウト／文脈失効、破棄とイベント解除、本番OFFをNode合成DOM試験で確認。
- 実機iPhone Safariでこの新コントローラを実行していない。実Garmin FIT（2026-11-03含む）の品質、実機のメモリや通信は評価していない。
- PRはUIコントローラ／自動テスト／文書／CIの**新規4ファイル**のみ。main統合でも既存公開画面の操作には影響しない。本人が最終承認するまでDraft・マージ禁止。
