# 今を知ろう：本番カレンダー行データ契約の照合（読み取り専用調査、2026-11-13）

## 確認結果
`index.html` の `fetchCloudRuns(options = {})` は既存RESTで `id,created_at,activity_date,name,distance_km,route,user_id,strava_id,source,started_at` を選択し、`user_id=eq.<currentUser.id>` と `deleted_at=is.null` で取得している。PR #102の独立アダプターが参照する `id,user_id,started_at` は**すでに取得項目にある**。追加DBカラムや取得API変更はこの範囲では不要。

既存カレンダーは `activity_date` で日付グループ化、同日複数ランを個別の `row` で表示。現状の個別ランボタンは `focusCloudRun(row)` で地図へ遷移する。**「今を知ろう」のボタンは未実装であり、既存の個別ラン／地図ボタンを上書きしない。**

## 留意点と未確認事項
- `started_at` カラムがSELECTにあることと、**各レコードで信頼できる開始時刻が入っていることは別問題**。値が欠損・不正なら拒否し、`activity_date` から推定しない。
- `deleted_at` はSELECTされないがREST側で除外されている。独立アダプターも渡されたオブジェクトに `deleted_at` が存在するときは削除済みを拒否する。
- `source` や `route` が含まれることだけで、詳細なGarmin FIT生データや認定済み1km区間が利用できるわけではない。GPS経路や時刻だけからセンサー値を捏造しない。
- `currentUser.id` はログイン所有者の識別。本番結線時はログアウト／ユーザー切替と非同期取得の競合を既存の `rrCalOwner` と照合する。
- 同日複数ランの表示や現在の地図遷移、iPhone UI、日英、配色はすべて本PRで無変更。
- 本番適用開始境界・実データの品質確認・導線文言・停止/自動ポーズ時の注意書きの結線は別途条件。診断は8日超で禁止。
