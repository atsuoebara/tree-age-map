# A-4 第4弾「成長する走行回数の節」独立監査依頼（2026-11-05）

**状態：開発ブランチ、未マージ・未公開。** 初30km・100回目はユーザー最終承認済み。PR #34のエラー独立化と安定ページングを維持する。

## 意図
100回目・500回目・1000回目の先も、ランニング歴の長い人（数千〜数万本）に達成済みの歴史と次の目標を提供する。**節目の上限は設定しない**。

## 判定ルール
- 既存の `fetchCloudRuns({stableOrder:true})` の本人データ全件（取得失敗時は計算しない）、FIT/Stravaの種目確認済みだけに限定。削除済み、不正な開始日時、無効な主キーIDは除外する。GPSなしは回数対象。別IDで同じ活動が二重保存されている場合は別々に数える。同じIDの重複は例外で認定しない。
- 既存の100回目と同様、開始日時昇順・同時刻はruns.id数値昇順を共通の基準とする。
- 節目の系列は100・500・1000、その先は1500・2000・2500・3000・…と500本刻み。対象件数に応じ、**到達済みの節目＋次の1件**を動的に生成。天井はない。
- UIは情報過多を避け、**最近達成した最大3件**を日付つきで表示し、**次の節目まであと何本**を表示する。進捗はHTML progress。既存100回目の詳細は別表示のまま。
- 今回のソース限定件数は、クラウドの総保存済みラン件数と一致しない場合がある。注記には対象範囲と、重複保存を1本ずつ数えること、過去分追加・削除で日付・残数が変わることを日英で明記する。
- 表示と日時は本人専用。ログアウト時に状態消去、言語切替で再描画。DB・Edge Functions・外部API・公開設定変更なし。

## 主な差分
- `a4-milestones-core.js`：`numberedRunMilestones(rows, verifier, targets=null)` を追加。対象行を1回精査して時系列ソートし、複数節目を一度に求める。`hundredthRun()` の公開インターフェース `{eligibleCount,record}` は保持して内部で関数を再利用。
- `a4-milestones-preview.js`：既存初30km/100回目の下に「これまでと次の節目」のコンパクトな読み取り専用表示を追加。独立try/catchのため新しい節目での例外は従来2件に伝播しない。達成済み最大3件＋次の目標と残り本数、日英対応。
- `index.html`：core/previewのキャッシュ版数変更のみ。
- `scripts/test-a4-milestones.cjs`：従来を含め**71アサーション合格**。99/100/101、499/500、999/1000、1434/1500、6000/6500、逆順・同時刻・削除・未知ソース・GPSなし・同一ID重複・不正targetsのチェック。
- JavaScript構文チェック（core/preview）合格。

## 独立監査の重点
1. 100/500/1000/以降500本刻みを無制限に作る算出ルールと次の節目（ちょうど到達時は次の500）が正しいか。
2. 自動生成の計算量・メモリ・画面表示が大量履歴のランナーでも実用的か（無制限に過去達成をDOM描画しない）。
3. 既存100回目判定・初30km地図導線が変わっていないか。エラー独立化が維持されているか。
4. 全件取得・認証・ログアウト・アカウント切替・日英更新の安全性。
5. 500本刻みの進捗と、100本のみ達成した人・対象ラン0件の場合の表示が自然か。
6. 重複や対象ソース限定、保存件数との違いが誤解なく表示されるか。
7. PR #31（モバイルコンパクト化・未マージ）/PR #32（横並び・マージ済み）とのUI干渉、狭いiPhone幅。
8. マージの可否。監査合格後はPages配信とユーザーのPC/iPhone最終確認を必須とする。

**本番・DBは未変更。監査担当はコード修正・マージ・デプロイせず独立監査のみ。**
