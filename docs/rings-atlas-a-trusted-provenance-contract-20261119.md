# Rings Atlas – 信頼できる来歴アダプタ設計 v0.1 (Atlas A / G3前段)

2026-11-19。**設計専用、未選定・未承認。本番データの取得・接続・実測・マージを認めない。** PR #280 (HEAD 55b443c5) の観測型・合成戻り値テストを前提とするが、その合格は実クラウド・実本人認証の証明ではない。

## 結論 / 信頼境界

**信頼できる来歴＝(a)実認証された owner とセッション世代、(b)権限が限定された実取得元、(c)一貫した時点の全ページ、(d)読み取り専用の端末記録、(e)全スコープ再計算の対象集合・版数、(f)表示/計測直前の失効再検査。** これらをひとつでも欠いた場合は `BLOCKED`。ランの表示数、事前キャッシュ、`currentUser` の存在、終了時に `getSession()` が成功したことだけでは証拠不足。

現行コードで確認できる事実（main 7661a6a0）：
1. `cloudEnabled()` は `currentUser`、`currentSession`、publishable key の存在を検査するだけで、本人データの全件取得を保証しない。`getCloudHeaders()` は `refreshCurrentSession()` を呼ぶため、要求ごとに `currentUser` が変わる可能性がある。**測定開始時 owner ID を不変に固定**し、要求前後に別途照合する必要がある（IDそのものを外部出力しない）。
2. `fetchCloudRuns()` は `id,created_at,activity_date,name,distance_km,route,user_id,strava_id,source,started_at` を50件ずつ `offset` 取得。`stableOrder` オプションがない通常経路は日付のみで並び、同一日多数のとき順序が一意とは限らない。**stableOrder=true を入れても、途中の insert/delete/update による offset 飛び・重なり、同一行のroute更新は防げない**。ソースの一貫性は別途証明が必要。
3. `start()` は `loadCloudRowsCache()` の前回キャッシュを表示し、後から `refreshCloudRowsInBackground()` する経路を持つ。キャッシュや `cloudRunCount`、一覧の件数は完全性証跡にならない。
4. `loadCloudActivities()` は取得・解析エラーを捕まえて0を返す。`buildActivityFromCloudRow()` は不正routeを `null` にできる。**0行や処理済み件数を成功証明に使用しない**。既存の重複排除による正当な減算と、解析失敗での欠落も区別する。
5. `loadSavedActivities()` は個別GPXの解析失敗を警告して処理を続け、`saveActivityToCloud()` を呼び得るため**測定用ソースに転用禁止**。`registerActivity()` もグローバル配列・キャッシュを書き換える。副作用ゼロの専用読取/解析経路が必要。
6. `getSelectedActivities()` は活動の `year` と活動 `date` の月を使う。`buildSelectedStats()` はrouteから導出済みの国・行政区ごとの距離を集計する。保存候補Aは既存定義・仕様版に結びつき、単純なDB合計での代替は不可。

## 最小の来歴契約（計測用のみ、後日別PRで試作）

### G3-P0 認証・所有者
- 測定開始前に認証SDKから現在のセッションを取得し、有効性確認を行う。ID文字列を自己申告の関数引数として受け入れない。トークンは**ブラウザの非公開メモリ内**でのみ扱い、ログ・URL・ハーネスの出力へ含めない。
- `ownerRef` と単調増加 `sessionEpoch` をメモリ内のみ固定。ページ要求、ローカル記録照合、集計、測定確定、Safari `pageshow.persisted` の各境界で同一owner/epoch・有効セッションを確認。ログアウト、別アカウント、トークン変更に伴う本人不一致、失効、タブ間の更新シグナルで即時破棄。
- 実認証の検査が済むまでは **成功申告フラグを生成しても権限証明にならない**。本人限定RLSはリクエスト境界で検査する必要がある。RLS変更やSQL追加は今回対象外。

### G3-P1 クラウドの全ページと一貫性
- 読取専用の新規経路で本人限定GETを発行し、HTTPステータス、JSON構造、各行の `user_id` 一致、異なる `id` の一意性、ページ位置・件数、最終ショートページまでを**実際の戻り値から**証明する。空の最終ページも許容し、50件ちょうどならもう1リクエスト必須。
- `stableOrder=true` 相当の **一意な順序 `activity_date.asc,id.asc` は必要条件にすぎない**。転送中にクラウド側で変化した場合でも全件同一版のスナップショットを保証する方法が未確定。候補：(A) サーバー側でownerに紐づく一定時点の読み取り版を持つ、(B) 前後で確実な更新世代・削除を含む整合性トークンを検証する、(C) 安全に読取できる一括スナップショットAPIを別途設計する。どれも現行APIで確立したとは言わず、仕様・負荷・追加費用0円・RLSを実証し選択する。
- `updated_at` や `deleted_at`、集合のハッシュ等が現行リクエストで利用可能かは**未確認**。単なる行数、開始/終了時の再GET、`created_at` やroute配列長だけでは更新検知が不十分。安全な版証拠がない限り BLOCKED とする。
- 失敗/期限切れ/一部ページ/署名不一致/HTTP 401・403・5xx/JSON不正/アクセス拒否はすべて失敗。再試行はownerと版の同一性を最初から検査し直す。結果を「0件」に丸めない。

### G3-P2 端末とその他の取込元
- ローカルGPXは**保存一覧の読取と全件パースだけ**を別関数にし、成功・スキップ理由・重複判定を明示する。1件でも読取/パース失敗なら計測を BLOCK（正当に対象外の種目は別途仕様確定）。端末→クラウド同期、レガシー復旧、Stravaバックグラウンド同期、記録登録を測定経路では絶対に呼ばない。
- 対象とする「全期間」は同一ownerに属する計測時点の**正本対象レコード集合**。クラウド正本とローカルの未同期記録・既存インポート、重複・屋内ランの扱いを固定しなければ、全件とは断言できない。iPhone/PC差や他端末の未同期ランも、契約外であれば「全本人データ」と誤表示しない。
- 地理境界データ（国内市町村、海外ADM1/2）のバージョン・取得成功・海外国別読込完了を証明。未取得の海外ADM2は無理に0とせず、既存の「—」規則を保持する。地理集計の完了もグラフィック/タイムラプスのロードとは区別。

### G3-P3 集計とスコープの同一版
- 完全な対象集合と境界版を固定してから、`all`、年、月を同一ソース版で算出。期間の期待スコープ集合をソース活動日から独立決定して照合（0件の月は0件と確定したものだけ扱う）。期間数だけ一致しても同一集合由来と証明できない。
- 合成テスト #273/#276 の現行関数を期待値の正本とする。将来の隔離計算が地理判定、重複、同日複数、走破地域数、海外ADM2「—」で一致する必要がある。
- 取得完了→全件解析→全スコープ計算→最後の認証・版数確認→ **その瞬間にだけ** #278 の容量投影を計算する。終了後にメモリから素データ・トークン参照を破棄。外部送信、保存、CIログ、URL、スクリーンショットへの個別地域名の表示は禁止。

### G3-P4 失効と時間制約
- サインアウト・owner変化・タブ復帰・履歴復帰・別タブ更新・計測途中の取込/削除、タイムアウト、読取キャンセル、ページ再読込時に測定結果を無効化。特にbfcacheは画面再表示**前**に本人再検証。
- 同一セッションでも取得中の `refreshCurrentSession()` で user ID が変わる可能性を織り込み、古いページ応答・遅れて返ったコールバックを epoch で破棄する。
- メモリ使用量が大きい場合は測定を中断し、上限設定・モバイルメモリ試験を別監査。上限超過を0や空データとして扱わない。
