# Rings Now PR #127: Safari bfcache実機証跡と旧タブ・ロールバック判断境界（2026-11-14）

## 本人の実機報告（事実と限界）
PR #126をマージし、本人がiPhone Safariの開始ページ→試験ページ→架空の5区間表示→「戻る」→「進む」を実施。本人の回答は「きえてるわ」、その後の表示確認は **「bfcache (persisted=true)」** だった。したがって**架空の5区間が消えていたこと、かつSafariが同じ文書をbfcacheから復元したことを本人が画面上で確認**した。これは本人の目視報告であり、ネットワークログや動画の取得を意味しない。

このPRのbfcache合格対象は **PR #126の架空数値だけを描くHTML**。PR #120の合成FIT実デコーダや実FITのメモリ消去を同条件で確認したとは言わない。実FIT、GPS、心拍、個人識別子は扱っていない。

## 旧タブ問題は未解決
公開GitHub Pagesのファイルを差し替え／取り下げても、以前に読み込んだブラウザタブ、bfcacheにある文書、HTTPキャッシュ、CDN上のコピーが即座に廃棄される保証はない。現行SWは合成解析ページを積極的にCacheStorageに入れないが、それはSafariのHTTPキャッシュや既存タブの破棄を保証しない。

**将来の旧タブ廃棄手順の想定**（実装済みではない）：
1. 公開を取り下げる／実FIT読取を停止する場合、既に動作中のページは残り得ると前提する。
2. 将来の各画面で明示的な公開バージョンと廃棄シグナルを安全に検証できる設計を検討する。ただし通信が禁止される設計とのトレードオフがあり、採否は未決定。
3. 不明な状態、バージョン不一致、非表示、セッション失効、撤回宣言は入力を閉じる。ページが外部停止シグナルを新しく受け取れなければ、自動で停止したとは言わない。
4. 取り下げ後の既存タブの挙動はSafari実機、CDN/HTTPキャッシュの残存は別検証として扱う。
5. 実FIT受入ページの公開、本人端末での利用、Rings Now本番ONはそれぞれ別々に本人が承認する。方式Aの14条件を機械的に満たしたと扱わない。

## このPRの隔離モデル
新規 src/rings-now-stale-tab-retirement-policy.mjs は**監査用の純粋関数**。呼び出し側が与えた loadedBuild / expectedBuild / 可視状態 / 失効状態 / ロールバック宣言 / 新鮮なシグナルの検証状態を判定する。どれか不足または不一致ならblocked。すべて正しくてもrequires_manual_reviewのみ。実FIT利用、本番ON、古いタブを強制停止できるという許可・保証はすべてfalse。ここでのfreshSignalVerifiedは自己申告値に過ぎず、シグナルの取得経路・安全性・本人同意は別審査が必要。**この関数はSafariに接続されていない**し、通信・キャッシュ・保存・実FIT解析を一切行わない。

新規4ファイル（隔離モジュール、テスト、この文書、CI）のみ。index、SW、公開HTML、DB、カレンダー、FITパーサー、本番OFF2点、PR #109 HOLDは変更なし。iPhone優先、追加費用0円、既存を壊さない方針。
