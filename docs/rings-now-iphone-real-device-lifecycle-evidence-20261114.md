# Rings Now：PR #124後のiPhone実機ライフサイクル検収（2026-11-14）

## 記録根拠
本人のこの会話での直接報告を記録する。これはテストの動画・Safari開発者ツール・ネットワークログに基づく主張ではなく、本人操作による目視報告である。

| 操作 | 本人報告 | 判定可能な範囲 |
|---|---|---|
| 合成FITで5区間を表示後、別アプリへ移動し元の画面に戻る | 「消えていた」 | iPhone実機・別アプリへの移動と復帰後、5区間が非表示だったことを確認 |
| 合成FITで5区間を表示後、別Safariタブへ移動し戻る | 「消えていたよ」 | iPhone実機・別タブ移動と復帰後、5区間が非表示だったことを確認 |
| 合成FITで5区間を表示後、URLで別ページへ移動し、Safariの「戻る」でテストページへ復帰 | 「消えていたよ」 | iPhone実機・履歴の「戻る」操作後に5区間が非表示だったことを確認 |

最初「前のページがないから戻れない」と報告があったため、別ページへ一度ナビゲートしてからブラウザ「戻る」で合成ページへ戻る操作に変更している。したがって**「進む」を試したことにはならない**。Safari内部でbfcacheが使用されたことを確認したわけでもない。

「ファイルを選択すれば復活した」件は、その後「同じファイルを読み込んで、確認を押した」と明示され、**新しい解析操作**に該当する。旧結果の無操作での復活と同一視しない。

合成ファイルの保存を繰り返して名前の末尾に数字が付いた可能性があり、厳密ファイル名制約とハッシュ照合によって再解析が拒否される場合がある。これもライフサイクル失効の成否と混同しない。合成FITの厳密制限は変更しない。

## 現時点の結論
**iPhone実機で3種類の操作後に古い5区間が表示されないことを本人が確認済み。** ただしSafariの「進む」、内部bfcacheの実利用、ブラウザのネットワーク監視、HTTPキャッシュ/CDN残存、実際の旧JSタブの強制停止を検証した証拠はない。

PR #122の14項目のうち、`iosSafariLifecycleTested`、`httpCacheAndServiceWorkerReviewed`、`incidentRollbackAndOldTabPlan`はこれだけで完全なtrueにできない。すべての条件は引き続き未認定・証拠審査待ち。自己申告フラグやテストPASSを実FITの許可に使わない。

### 次の検証で優先するもの
- iPhone Safariの「進む」操作および実bfcache観測方法。操作が再読み込みだった場合とbfcache復帰の場合を区別。
- 公開した静的JSの差し替え・撤去後のHTTPキャッシュ/CDNと既に開かれたタブの挙動を、合成データのみで検証する計画。
- CSPだけで制御できないDOM/リンク/画像/フォーム/ナビゲーション送信経路を、全依存で監査。
- iPhone実機の通信観測方法（PC必須や追加費用が生じる場合は採用しないで代替と限界を提示）。
