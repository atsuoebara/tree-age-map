## ユーザーの当初目的へ戻すための最短ルート

本来の目的は「情報量過多のホームから地域別詳細を専用ページに移す」こと。新しいDB集計・持続キャッシュを先に作る必要があるとは確定していない。以下の**既存処理再利用ルート**を先に比較する：

1. **見た目を先に整える**：既存ホームの地域別詳細は新ページへのリンクを提供する。既存の集計・所有者境界を変えず、画面を段階的に分ける。地図と地域内訳の切替が同じ認証画面で済む方法を優先。トップの地域詳細削除は別承認が出るまで禁止。
2. **A方式の新規保存は保留**：今回の一連の容量・来歴PRは将来のパフォーマンス課題用の検証資産として維持する。単にページを移すだけなら、DB一貫性プロトコルを新たに実装しなくて済む実装を検討。
3. **既存 owner/RLS とGPS取得の再利用**：二重ダウンロード、ログアウト後表示、同月2件、ADM2「—」、期間の選択、地図ハイライトを変えない。ページ遷移時の状態保持は必要に応じて期間のみ・個人GPSをURLへ出さない。
